# 架构与失败恢复

## 三条主线

访客消息通过 HTTP 或 WebSocket 到达 Go。服务器不接受客户端指定发送者身份，从 Cookie 查询数据库会话，锁定会话行后检查权限、消息状态和附件归属。客户端的 `client_id` 与发送者、会话组合唯一；重复请求返回原消息。

数据库事务同时增加 `last_seq` 并写入消息，然后才 ACK。前端 ACK 表示“已保存”，不是对方已读。前端补拉游标只从完整查询结果推进，避免 ACK 先到导致跳过其他消息。

AI 状态下，访客消息和持久任务同事务提交。Worker 用 `SKIP LOCKED` 领取任务并获取递增租约代次。模型请求在事务外执行；最终回复和任务完成在一个事务中提交，必须同时满足租约拥有者、代次、截止时间、会话版本和 AI 状态。故障恢复可能重复调用模型，但不会接受两个最终结果。

## RAG

文档上传保存原始文件，`document_versions` 记录处理任务。解析后按约 700 Unicode 字符分段、100 字符重叠，最多 1000 个片段。PDF 保存页码；TXT/Markdown 保存段落标识。云端生成 1024 维向量，pgvector 用余弦距离做精确 top-5 检索。

检索仅使用启用、未删除文档的当前可用版本。替换版本先全部处理成功再原子切换，失败保留旧索引。向量模型与端点组成指纹，不同指纹禁止混用。引用必须来自当前轮真实检索；提交答案前再确认文档仍处于可用状态。

模型工具白名单仅包含 `search_knowledge`、`request_handoff`。最多三次工具调用，最终输出经过结构校验；无引用的业务回答不接受。问候可以不检索，最多允许一次澄清。资料文本和图像内容是数据，不能扩大后端工具权限。

## 人工交接

四态：`ai → waiting → human → closed`；人工可 `human → waiting` 退回。访客、当前客服或管理员可在授权范围关闭会话。

转人工立即增加会话版本，取消 pending/running AI 任务，记录转接原因及近期对话的提取式摘要。摘要直接来自消息，不依赖另一次模型成功。即使云请求不能取消，最终版本检查也拒绝迟到回复。接单与改派使用同一会话行锁，因此不会分配给两名客服。

## 双实例

Nginx 在两个 Go 实例间分发请求，WebSocket 可落在任一实例。Cookie 身份保存在 PostgreSQL；附件使用同主机共享卷。Redis 广播会话编号，实例只通知有权限的本地连接。Pub/Sub 不持久，数据库是消息真相来源；前端重连和定期补拉恢复遗漏。

慢客户端的发送队列有上限，满时断开该连接，随后重新连接补拉。在线状态通过有期限的 Redis 记录维护，旧连接退出不删除新连接的记录；实际是否可接待还须检查账号启用和 available 状态。

## 故障边界

| 故障 | 行为 |
| --- | --- |
| 应用提交后、ACK 前退出 | 客户端使用相同 client_id 重试，得到原消息 |
| Redis 丢通知 | 重连或周期查询从数据库补齐 |
| 模型超时或无依据 | 有限重试后转人工，不编造成功回复 |
| AI 执行实例退出 | 租约到期后其他实例领取，旧租约不能提交 |
| 文档处理失败 | 状态和错误可见，可重试，旧版本保持可查询 |
| 用户要求人工时模型仍生成 | 状态版本和租约检查拒绝旧输出 |
| 无客服在线 | 保留等待与留言，不预测等待时间 |

Redis 故障时当前实现限流会降级；此项目不承诺中间件完全故障下保持全部防滥用能力。生产环境需配置中间件高可用和外层限流。
