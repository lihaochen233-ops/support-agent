# 建议学习路线

先把人工聊天跑通，再学习 AI。每个阶段都能通过页面或测试观察实际效果。

1. **启动与接口：** `cmd/server/main.go` → `config.go` → `server.go`。理解环境变量、路由、context、超时和优雅关闭。
2. **身份与权限：** `auth.go`。匿名身份和客服身份为何用不同 Cookie？数据库保存令牌哈希有什么作用？CSRF 与 Origin 分别保护什么？
3. **聊天事务：** `chat.go` 的 `sendMessage`。沿着鉴权、行锁、幂等查询、seq 分配、消息保存、任务插入、提交与通知逐步阅读。
4. **接单与状态机：** `handleTransition`、`handoffTx`。同时点击接单为什么只有一个成功？为什么转人工要增加版本？
5. **Go 并发通信：** `realtime.go`。每连接发送队列、读写循环、超时、取消、慢客户端和 Redis Pub/Sub。
6. **知识入库：** `knowledge.go`。从文档版本到解析、分段、向量化和索引切换。上传文档与训练模型有何区别？
7. **Agent：** `provider.go` → `ai.go`。真实 HTTP 工具调用、图片 data URI、结构化结果、引用验证与转人工。
8. **任务恢复：** `claimAIJob`、`renewAILease`、`finishAIJob`。租约过期后旧 Worker 为什么还可能返回？fencing token 如何阻止它提交？
9. **前后端联调：** `frontend/src/components/ChatPane.vue`、`realtime.ts`。ACK、重新连接与补拉游标为什么不能混为一谈？

## 面试中值得讲清楚的六件事

- ACK 只承诺消息持久化，无法承诺对方已看到。
- 向量相似度不是事实正确率，引用验证也不能代替真实问答评估。
- 数据库是正确性边界；Redis 通知丢失可以补拉，不能依赖 Pub/Sub 保证不丢消息。
- Agent 只能调用服务器授权的两类工具，不能自行退款或查询任意文件。
- 转人工是一项数据库状态变更，不取决于模型是否愿意执行。
- 云请求可能被重复执行，但通过代次、版本和事务保证最终只接受一份回复。

项目描述应填写真实运行环境、测试方法和实测指标；不要写“百万并发”“零幻觉”或未经测量的准确率。
